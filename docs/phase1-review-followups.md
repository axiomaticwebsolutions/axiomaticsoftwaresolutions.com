# Phase 1 review follow-ups

Low-severity findings from the Phase 1 security, domain and design/accessibility reviews (2026-10-06).
All high and medium findings were fixed except the refund-reversal snapshot, which is now in the schema.
Fold each item into the phase that next touches the code.

| # | Area | File | Finding | Suggested fix |
|---|---|---|---|---|
| 1 | security | `lib/db.ts:41` | Prisma validation errors print argument values (password and token hashes) to stdout, outside the redacting logger | Pass `errorFormat: 'minimal'`. Use `log: [{ emit: 'event', level: 'error' }, …]` and forward the events through lib/log (event name and code only). Refuse PRISMA_LOG_QUERIES when NODE_ENV=production. |
| 2 | security | `lib/licensing/keys.ts:26` | redactLicenseKeys misses key forms that normalizeLicenseKey accepts as valid (spaces, en dash, full-width characters) | Allow `[\s\-‐-―−﹘﹣－]?` between groups in KEY_IN_TEXT_RE and match against an NFKC-normalised copy (or use a `u`-flag regex over `\p{L}\p{N}`), masking the original span. Add tests for each variant that normalizeLicenseKey accepts. |
| 3 | security | `lib/auth/password.ts:49` | verifyPassword returns immediately for empty or oversized passwords while verifyAgainstDummy does a full argon2 check, exposing account existence through timing | Make both paths do the same work. In the early-return branch, `await verifyAgainstDummy(password)` (it already slices to the maximum length), or make verifyAgainstDummy skip work for the same length bounds. Also cap the sign-in schema's password at 1..1024 characters. |
| 4 | security | `lib/auth/tokens.ts:13` | Unkeyed SHA-256 is used for low-entropy values (rate-limit IPs and emails, 6-digit verification codes), so the hashes are reversible | Use HMAC-SHA256 with a server secret (e.g. a key derived from SESSION_SECRET with a purpose label, as lib/storage/local.ts does) for rate-limit identities and for 6-digit and URL codes. Keep plain SHA-256 only for 256-bit random tokens such as session tokens. |
| 5 | security | `lib/auth/rate-limit.ts:162` | Per-IP sign-in limit is 20 per 15 min; the contract says 5 failures per 15 min per email and per IP | Set the limit to 5, or record the deviation (for example, to allow for shared NAT) in docs/decisions.md. |
| 6 | security | `lib/env.ts:177` | Production config does not require REDIS_URL, and rate limits silently fall back to Postgres | Add `if (!raw.REDIS_URL) problems.push('REDIS_URL: is required when NODE_ENV=production')`. Make storeFor() throw in production when no store has been registered with setRateLimitStore(). |
| 7 | security | `lib/payments/mock.ts:181` | Mock provider's signing helpers and constructor have no production guard and use the real webhook secret with Razorpay's webhook signature format | Throw a PaymentProviderError('not_configured') from the MockProvider constructor and from every exported sign/build/capture helper when isProduction(). Gate each /api/dev/* handler and each dev server action on its own (the layout check does not protect them). |
| 8 | security | `prisma/seed.ts:20` | Seed's only production guard is NODE_ENV, and the seed writes publicly known license keys and demo staff logins | Also refuse unless the DATABASE_URL host is localhost, 127.0.0.1 or ::1, or an explicit ALLOW_SEED=1 is set. Optionally refuse when the database already holds non-seed orders. |
| 9 | security | `next.config.ts:135` | Production CSP allows 'unsafe-inline' scripts, so it gives no XSS protection | Move to a nonce-based CSP (middleware generates a nonce; Next applies it to its scripts) before the key-reveal and portal pages ship. At minimum, record the deviation and target phase in docs/decisions.md. |
| 10 | domain | `lib/licensing/terms.ts:129` | A per-unit subscription renewal can lower deviceLimit below the number of active devices | Either make the checkout pin RENEWAL qty to the license's current deviceLimit for per-unit plans, or reject qty below the license's active device count. At minimum, keep deviceLimit at max(qty, active devices) and record the deviation in decisions.md. |
| 11 | domain | `lib/licensing/status.ts:63` | The licensing.expiringDays setting is never used, because the derived status hard-codes 60 days | Add an optional expiringDays parameter to deriveLicenseStatus()/isUsableLicense() and pass settings.licensing.expiringDays, as selfServiceResetsLeft() already does for its limit. Otherwise, remove the setting. |
| 12 | domain | `lib/rbac.ts:271` | trials.start excludes the Viewer role, but api-contracts allows any team role | Add VIEWER to trials.start, or record in decisions.md that Viewers cannot start trials (read-only role). |
| 13 | domain | `lib/config.ts:182` | One invalid stored field silently replaces the entire seller/tax section with placeholder defaults | For the business and tax sections, fall back per field rather than per section. Better, make invoice issuance and checkout fail closed (refuse with an alert) when the stored business/tax settings do not parse, instead of using placeholder seller details. |
| 14 | design-a11y | `components/ui/dropdown-menu.tsx:156` | Shortcut text drops to 4.20:1 on a highlighted menu or command item | Add `group-data-[highlighted]:text-lavender-fg` / `in-data-[selected=true]:text-lavender-fg` (or inherit with opacity no lower than 4.5:1) to the shortcut classes, or use ink-2 for shortcut text. |
| 15 | design-a11y | `components/ui/input.tsx:16` | Input sizes do not match the prototype's radius, weight or 40px portal size | Set md to rounded-12 and add `font-semibold` to controlVariants and textareaVariants. Add a portal size (`h-10 rounded-10 text-[14px]`), or document which prototype sizes map to sm/md/lg. |
| 16 | design-a11y | `components/ui/field.tsx:102` | Inline field errors are not announced when they appear | Render FieldError inside a persistent `aria-live="polite"` container (always mounted, so the insertion is announced), or give it role="alert" for errors raised outside a submit. Do the same for ConfirmDialog's inline errors. |
| 17 | design-a11y | `lib/design/tokens.ts:51` | The shadcn 'muted' aliases that decisions.md promises do not exist | Add `muted: { DEFAULT: palette.slate.bg, foreground: palette.ink["2"] }` to `semantic`. Merge it with palette.muted.icon, or rename that key so they don't collide. |
| 18 | design-a11y | `lib/design/tokens.ts:48` | Two chart colours fail the 3:1 non-text contrast minimum against white | Darken those two entries to at least 3:1 (e.g. #8F82E0 instead of #B9AEF2, and #7C8597 instead of #9AA3B2), or record in decisions.md that charts must add direct labels or patterns so colour is not the only cue. |
